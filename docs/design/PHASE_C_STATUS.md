## Review chain outcome

**W6** found three MAJORs, all real and all reproduced independently by the orchestrator before the fix round:

1. **Focus was lost after closing a settings overlay** — `push_overlay()` recorded the opener *after* `add_child`, so it captured the overlay's own control (or `<null>`).
2. **`ui_scale` did nothing visible** — the theme pinned explicit per-type font sizes, which shadow `Theme.default_font_size`, so the scaled default never reached a widget.
3. **The minimap was not player-centred** — blips were plotted in absolute world coordinates; the self blip sat 299.3 px off an 84 px disc at (9000, 7000).

**W7** fixed all ten actionable items (the three MAJORs plus seven MINOR/NOTE items) and reported measurements, not assertions: opener captured before `add_child` (`router.gd:119-124`), player-centred minimap (`_blip_origin()`), `_scale_font_sizes()` scaling all 21 font items in `Router.live_theme()` without compounding, the `DialogTitle` 18 / `Version` 13 / `SlotNumber` 10 variations replacing per-node overrides, all `print()` calls removed (gated `push_warning` in `game.gd`), boot/loading colour literals replaced by `_token()` lookups, `Hud.set_cargo_open()` plus the `cargo_toggle` action wired in `game.gd`, the settings `ui_cancel` closer, `Hud` receiving `Router.live_theme()`, and the reticle micro-bar moved into a container (60×4 preserved). The theme was regenerated by running `tools/build_theme.gd`.

**W8** re-measured every W7 claim with a temporary SceneTree probe, four headless runs and the live editor: **CLEAN on all 10, 0 BLOCKER, 0 MAJOR.** It added B1–B5, none reachable from shipped Phase C paths.

## Residual items (no action taken — recorded on purpose)

1. **INFO — the loading screen was never photographed mid-transition.** The boot → loading → menu sequence completes faster than a screenshot round trip; the only way to catch it is a deliberate delay, which would mean editing a shipped script. The scene itself runs clean headless and was verified to load and route.
2. **INFO — unconsumed assets by design:** `ui_panel_frame.png`, `ui_slot_inventory_*.png`, `icon_credits_*`, `icon_logout_*`, the 16 px weapon cuts and the 48 px glyph cuts. They are catalogued in `docs/ASSETS.md` and belong to later phases.
3. **INFO — `DialogManager` beyond the quit dialog is unexercised** until a real in-game dialog exists. W8 did drive the external-pop/queue recovery synthetically (stack walked back correctly), so the mechanism is verified even though no shipped screen uses it yet.
4. **NOTE (W8 B4) — `tools/build_theme.gd:338` reports `variations: 12`** while 11 are actually registered: `MenuButton` is deliberately skipped by `NATIVE_CLASS_NAMES` because it is a built-in class. Cosmetic reporting only; the `MenuButton` *items* are still stored and still scaled.
5. **NOTE (W8 B5) — the editor's own caches** (`.godot/uid_cache.bin`, `.godot/editor/filesystem_update4`) still hold the string `_probe` after a filesystem scan. Nothing matches `tools/_*` on disk; these are engine cache binaries, not project files.
6. **INFO — display-mode and resolution changes cannot be validated in the editor-embedded game window.** `SettingsManager._apply_graphics()` sets `window.mode` / `window.size` correctly, but neither a settings-screen change nor a direct `Window.mode = MODE_FULLSCREEN` assignment sticks while the run is embedded (confirmed live: `mode` stayed `0` in both cases, `window.size` stayed 1152×648). Verify these two options in a **standalone** run (`..._console.exe --path <proj>` with no editor open), not through `project_run`.
7. **INFO — an input quirk seen once while clicking the UI SCALE groove** in the embedded run: a click at framebuffer (1000, 115) produced 0.85× (the minimum) where the same click had produced ~1.40× before the fix round. The point is inside the measured slider rect (`/root/Router/OverlayLayer/Settings/Panel/Margin/Layout/Tabs/INTERFACE/UiScaleRow/UiScaleSlider`, global rect x=798 y=101 w=240 h=16, min 0.85 max 1.5). Every value path was verified independently (slider → `SettingsManager` → `Router` → theme, at 1.0 → 1.4 → 1.0 with no compounding), so this is an input-injection artefact, not a code finding. Drive the value through `SettingsManager.set_value()` when scripting the check.
8. **INFO — two orphan `crush` processes** from the killed first attempt are still alive with their own `godot-ai`/`godot-lsp-bridge` children. They write nothing; left alone deliberately rather than risk killing the user's own session.

## Where Phase C leaves the project

The game is playable end to end: `boot → main_menu → (settings | quit confirm) → loading → game (HUD, cargo, reticle, minimap) → loading → main_menu`. Everything visible is themed from `vajb_theme.tres` tokens, the UI scales with one setting, and every screen was inspected through the live editor's game capture during this pass. Note that `editor_screenshot` returns its image inline to the agent and offers no output path, so **the visual evidence exists only in the session transcript** — the machine-checkable evidence on disk is `.agents/gen/review_report.md`, `fix_report.md`, `review2_report.md` and `headless_sweep.log`.

**Next phase candidates**, in the order the specs suggest them:

1. Consume the remaining Phase B assets (the panel frame, the inventory slot art, the credits/logout icons, the weapon cuts) — `docs/design/ASSET_WIRING_HANDOFF.md` already lists them.
2. Real content behind the HUD: a second weapon hardpoint, a working target list for `TargetReticle`, and a first `DialogManager` consumer.
3. Audio wiring: the buses exist and `main_menu.gd:80,84` plays the two UI cues (`ui_hover` / `ui_click` — both files ship in `assets/audio/ui/`), so menu feedback is live. Nothing else is wired: no music is ever started (only the `Music` bus volume is applied) and no gameplay cue plays, although `AUDIO_SPEC.md` and 120+ `.ogg` assets are in place. A music start on boot/menu and a weapon/impact cue pass are the next cheap wins.
4. The screens' remaining states: the loading screen's mid-transition capture, and a standalone pass over the display-mode/resolution options (residual item 6).
