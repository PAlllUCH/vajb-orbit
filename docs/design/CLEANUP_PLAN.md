# Vajb Orbit — cleanup plan (docs, artifacts, working set)

Prepared 2026-09-18 while engine wave 1 runs. **Nothing here executes while a
worker wave is in flight** — docs are the workers' law, so cleanup lands only
in a quiet window (after engine wave 1 closes, or between waves). Every
disposition needs the owner's tick before it happens.

---

## 1. Principles

1. **Evidence chains survive.** Reports (`*_report.md`) are cited by the
   design docs as proof — they are never deleted; executed *task briefs* are
   (AGENTS.md already sets this rule). **Amendment 2026-09-21 (owner):** the
   chains are consolidated, not deleted outright — per-worker reports and run
   logs went, wave-level + review reports and `.agents/gen/MASTER_REPORT.md`
   remain as the cited evidence.
2. **Archive, don't vanish.** Retired records move to `docs/archive/` with a
   one-line README index; links from AGENTS.md/ENGINE_SPEC are repointed in
   the same pass. Hard deletion is reserved for true dead weight (executed
   briefs, probe output, dead mock scenes).
3. **Docs-first holds.** A doc is only retired after its live content is
   absorbed by the doc that supersedes it (merge → archive), and AGENTS.md's
   doc map is updated in the same pass.
4. **Generated files are never "cleaned"** — `vajb_theme.tres`,
   `ASSET_CATALOG.md`, import caches are regenerated by their scripts, never
   hand-edited or deleted.
5. **One pass, one report.** The cleanup runs as its own mini-wave with a
   report listing every file touched, before/after state, and zero broken
   references (grep-verified).
6. **The archive is sealed.** `docs/archive/` is blocked for agents by the
   PreToolUse hook `.crush/hooks/protect_archive.py` (registered in
   `crush.json`): any tool call whose input mentions the path is denied
   unless the owner launched the session with `VAJB_ARCHIVE_OK=1`. The
   reference-audit grep that mentions archive paths needs that flag set for
   the run — owner grants it, nobody self-serves.

## 2. Disposition classes

- **KEEP-ACTIVE** — still the law a coder reads today.
- **ARCHIVE** — move to `docs/archive/` (or leave provenance folders in
  place, marked); content absorbed where noted.
- **DELETE** — executed briefs, dead scenes, probe output; no evidence value.
- **MERGE-then-ARCHIVE** — the live sections move into the successor doc
  first, then the shell is archived.

## 4. Execution process (the mini-wave)

1. **Gate:** no worker wave in flight; engine wave 1 closed (or paused at a
   slice boundary).
2. **Owner sign-off** on this table (tick or veto per line).
3. **Reference audit:** grep each retiring path across `docs/`, `AGENTS.md`,
   `ENGINE_SPEC.md`, `vajb-orbit/` and `.agents/gen/*_report.md`; every hit
   is repointed (or the citation line is updated to the archive location)
   before the move/delete happens. Runs with `VAJB_ARCHIVE_OK=1` (owner-
   granted) because the citation lines name the archive path.
4. **Merge first:** `MAIN_MENU_SPEC` boot/loading content lands in
   `MAIN_MENU_V2` (owner approves the target); `TESTING_NOTES` dispositions
   become an IMPLEMENTATION_PLAN amendment line.
5. **Execute:** create `docs/archive/` + `README.md` index (one line per
   archived file: why retired, what superseded it); move ARCHIVE items;
   delete DELETE items.
6. **Update AGENTS.md's Documentation Map** in the same pass — it must match
   disk exactly afterwards.
7. **Verify:** grep for every deleted/moved path returns zero live
   references; the doc map matches the tree; report written to
   `.agents/gen/cleanup_pass_report.md`.

## 5. Expected outcome

Working doc set shrinks to the ~20 live contracts + the 7-sector RPG layer;
executed-phase records (B/D/E plans, Phase C status, D1 audit, three menu
supersessions, ~30 executed briefs and their probe run logs) leave the
working set without losing a single evidence chain. Future passes repeat the
same four steps after each phase closes.
