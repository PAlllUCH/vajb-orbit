# S2.6-R1 report — gate hermeticity (CONTRACTS §14, L90/L93)

## Result

The gate no longer reads or writes the owner's live account. `tests/headless_runner.gd` creates
`user://_gate_scratch/`, repoints `PlayerProfile.save_path` inside it, resets the **in-memory**
profile and seeds the deterministic default at runner boot; every `EconomyLog` write that is not
already a suite's own scratch goes to the same sandbox. The four live-coupled tests build their
own fit fixtures (index-guarded) and wire's one assertion reads the launched fit.

- **Before** (live profile present, unfixed tree): `[SUMMARY] passed=433 failed=4`, exit 1 —
  `test_engine2_dock.gd` ×2 (`the launch seeded the live pack from the store (300 of 300)`,
  `the first settle charges its three (300 -> 300)`), `test_engine2_fixes.gd` ×1
  (`the launch seeded the live pack from the store (300 of 300)`),
  `test_engine2_wiring.gd` ×1 (`and the laser is in the fit`). Measured twice (20:01 and 20:16).
- **After** (two consecutive runs, **mutated** live profile present, md5 `1e4507e7…`):
  `[SUMMARY] passed=440 failed=0`, exit 0, both runs; the two logs are byte-identical except the
  L91 leak line (26 ObjectDB / 12 resources vs 84 / 36). 36 suites, 440 tests.
- **Final tree** (reconstructed live profile, md5 `3c9c167b…`): `passed=440 failed=0`, exit 0.

`437 + 3 = 440`; no other count moved (per-suite census in Evidence).

## Deviations

1. **`test_engine2_pools.gd` is outside the brief's "Tests that move" list.** It had to move: it
   was the one suite that restored the literal live path, which the new boot sequence makes wrong.
   Reversal: restore `Profile.SAVE_FILE`.
2. **The live `profile.cfg` was destroyed and reconstructed — read this one.** During the first
   full run of the new harness (run A, 20:21) `test_engine2_pools.gd` handed the store to the live
   path and this wave's own hygiene test then wrote its mutation to "the store's path" (guard
   added since). `user://profile.cfg` now holds a reconstruction from the fields
   `S2.6-R0_report.md` §0 recorded **before** the incident (`save_version=5`, `credits=852`, the
   Vanguard fit's W cells `["w_mining", "w_cannon", ""]`, packs at the shipped 300); every field
   R0 did not record is at the shipped default, so the file is 359 B against its original 2151 B
   (md5 `bb2ad1d7…` → `3c9c167b…`; the mutation that had replaced it, `1e4507e7…`, is in the AC1
   table below). **Owner action:** the Windows host's own
   `%APPDATA%\Godot\app_userdata\Vajb Orbit\profile.cfg` is the only remaining copy of the exact
   account — copy it over if the reconstructed defaults are not acceptable. The recovery rewrite
   is one `ConfigFile.save` of those five recorded fields (the probe is quoted in Evidence, run
   once and deleted).
3. **`_sandbox_log()` is conditional, not unconditional.** Re-applying the sandbox before every
   method unconditionally broke the twelve log-reading tests (`test_p1_clock_log`, `test_p1_market`
   ×3, `test_p1_profile`, `test_p1_refinery` ×2, `test_p1_repairs` ×2, `test_p2b_retirement` ×3):
   it clobbered the scratch path they set for themselves. Only the live `DEFAULT_PATH` is now
   replaced. Reversal: drop the `if` (and accept those twelve failures).
4. **Hook workaround (L92's defect, evidence for it).** `.crush/hooks/enforce_worker_files.py`
   normalises only the Windows workspace root, so every absolute Linux path is denied as "outside
   this worker's declared file set" — including `vajb-orbit/tests/…`. All edits in this pass were
   made with workspace-relative `file_path` values, which the hook compares correctly. No file
   outside `vajb-orbit/tests/` was touched.
5. No pinned number was invented; no `game/`, `docs/`, `project.godot` or asset file was touched.
