## 6. Deviations and decisions taken inside the pin (ladder bucket 1)

1. **The jitter sits at the three call sites, not inside `spawn_chip_sparks` /
   `spawn_shield_ripple`.** The amendment is the *beam's* amendment ("the engine-drawn beam …
   gains two numbers"; owner: "**a beam's** hit should spawn its impact FX …"), and the pin counts
   the two chip reads separately from the ripple, so the three readers are read *sites*. Consequence
   that this decision controls: a **projectile**'s shield ripple (`projectile.gd:1576`) does **not**
   move. Reversal: move the scatter inside the two spawn helpers (one line each) if the reading is
   meant to be the functions rather than the sites.
2. **`Projectile.collision_radius` searches the target's subtree.** A ray hands back the bare
   `HullBody` for a hull but `_sink_for` hands back the *ship* for the shield rule; both must read
   the same 30 u, so the walk is depth-first in child order (the hull's own collider wins over
   anything mounted after it) and stops at the first circle. Measured: both read 30.0.
3. **`HIT_FX_JITTER_MIN` / `HIT_FX_JITTER_MAX` are named.** The pin's numbers (8/48) are only named
   inside its clamp expression; the project's own convention is a named const per number.
4. **A private `_fx_rng` per component** (the pattern `asteroid_field.gd:116`,
   `player_ship.gd:191` and `sector.gd:94` already use) rather than the global RNG, so the effects
   cannot perturb the gameplay streams a seeded run measures.
5. **Uniform in the disc via `sqrt(rng.randf())`** — the pin says "a uniform random point in that
   disc", which is uniform per unit area; `scatter_in_disc` returns `at` untouched for
   `radius <= 0.0`, which is the reversal (`HIT_FX_JITTER_MULT 0.0`).
6. **`_hit_fx_parent` mirrored into `mining_laser.gd`** (its own `_world_parent` fallback), so the
   shaft's burst hangs where a gun's does.
