## 1. Finding 1 (MAJOR) — focus opener recorded after `add_child` — **FIXED**

- File: `autoload/router.gd:117-124`.
- Change: `var opener := _focus_weakref()` (line 119) now runs **before** `_overlay_layer.add_child(instance)` (line 120); the overlay entry on line 124 stores that value. ```

The reviewer measured `recorded opener = ResolutionOption` and `focus after pop = <null>`; the opener is now the menu button and focus returns to it.

## 2. Finding 2 (MAJOR) — minimap plotted absolute world coordinates — **FIXED**

- Files: `ui/hud/minimap.gd:5-7` (header doc rewritten: the squares are centred on the self blip), `ui/hud/minimap.gd:90-106` (`_draw_blips`), `ui/hud/minimap.gd:109-117` (new `_blip_origin()`).
- Change: the origin is derived from the `self` blip and every blip is plotted as `offset = (world - origin) * unit`; the self blip is drawn at the centre unconditionally, and the off-disc skip now applies only to contacts (`if kind != KIND_SELF and offset.length() > usable`). If no self blip is present the origin falls back to `Vector2.ZERO`, i.e. the old absolute behaviour, so a caller that sends only contacts still draws something.
- Evidence — live game, ship teleported to (9000, 7000) (well outside the 3200 u radius, where the old maths blanked the map), then read back through the HUD node:

```
player=(9000.0, 7000.0) origin=(9000.0, 7000.0) origin_follows_self=true self_draw_offset=(0.0, 0.0) | nearby contact offset=21.9px vs usable=84.0px (drawn) | old absolute self offset=299.3px (would be skipped)
```

168 px minimap ⇒ 84 px usable radius; a contact 720/−420 u from the ship lands 21.9 px from the centre and is drawn, while the old absolute origin would have put the self blip 299.3 px out and skipped everything. The origin reflects the last blip set pushed (the game pushes at 10 Hz), which is the correct input for the draw.
